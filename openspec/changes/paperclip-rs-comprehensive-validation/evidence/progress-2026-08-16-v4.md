### R664 - Auth Boundary 修复
- **根因**：`auth_layer` 只注入 anonymous，不强制 board 身份
- **修复**：
  1. `auth_layer` 在 `local_trusted` 模式下自动注入 `Actor::User { id: "local-board", is_instance_admin: true }`
  2. 新增 `require_board_layer` middleware（与 Node `routes/authz.ts::assertBoard` 等价）
  3. pc-server 装配：执行顺序 `board_mutation_guard → auth_layer → require_board_layer → csrf_layer → handler`
- **验证**：
  - AUTHENTICATED: `/api/companies` → 403 (Board access required)
  - LOCAL_TRUSTED: `/api/companies` → 200 + 17 companies
  - `/api/health` 两种模式都 200
- **单测**：10 passed（含 4 新增 require_board_layer tests）

## 本会话关键发现 (v3 → v4)

1. **Auth boundary bug 真实存在**：未认证请求返回 200（违反 Node assertBoard 行为）
2. **axum layer 顺序陷阱**：`.route_layer()` 后加的在外层先执行；require_board_layer 必须
   源码中**先**加，才能在 auth_layer 之"内"执行（读取注入的 AuthContext）
3. **local_trusted 缺失**：Node 默认注入 local-board，Rust 之前没有这个 fallback
4. **公开路径豁免**：/api/health 等需要在 require_board_layer 白名单中豁免
